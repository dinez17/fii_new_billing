# Database Design — Key Decisions

Full schema: `packages/database/prisma/schema.prisma` (~55 models). This doc records the *why*.

## Tenancy
- Every tenant-owned table has `tenantId`; all unique constraints are composite with `tenantId` (e.g. `@@unique([tenantId, invoiceNumber])`).
- Prisma client extension auto-injects `tenantId` into every query/create. Optional Postgres RLS as second layer.

## Critical constraints (business-rule enforcement in DB)
- **Duplicate invoice prevention:** `@@unique([tenantId, subscriberId, periodStart, invoiceType])` on Invoice + `@@unique([tenantId, cycleType, periodStart])` on BillingRun.
- **Duplicate payroll prevention:** `@@unique([tenantId, year, month])` on PayrollRun; `@@unique([payrollRunId, employeeId])` on Payslip.
- **One attendance per employee per day:** `@@unique([tenantId, employeeId, date])`.
- **Webhook idempotency:** `@@unique([gateway, eventId])` on WebhookEvent.
- **Gateway order idempotency:** `@@unique([tenantId, gatewayOrderId])` on Payment.
- **Consumer idempotency:** ProcessedEvent PK `(consumerGroup, eventId)`.

## GST modelling
- Invoice/PurchaseInvoice/Expense store `cgst/sgst/igst` split at both line and header level; `isInterState` decided by comparing tenant `stateCode` vs `placeOfSupply`.
- `GstTreatment` (B2B/B2C/EXPORT/SEZ/NIL) drives GSTR-1 bucketing; B2B requires customer GSTIN (validate regex `^[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z][1-9A-Z]Z[0-9A-Z]$`).
- HSN/SAC on every line → HSN summary report. Credit/Debit notes carry their own GST split → CDNR/CDNUR sections.
- GSTR-1/3B are computed reports (no stored aggregates) generated by report-worker from invoices, notes, expenses within date range.

## Accounting model
- **Party ledger** (LedgerEntry): debit/credit per customer/supplier. Customer outstanding = openingBalance + Σdebits − Σcredits. Written ONLY by ledger-worker (single writer) from events → invoice=debit, payment/credit-note=credit; purchase-invoice=credit(supplier), supplier-payment/purchase-return=debit.
- **Day book**: every cash/bank movement, with `DayBookClosing` snapshot per day (opening + in − out = closing; next day's opening = previous closing).
- Financial rows are immutable — corrections via reversal entries. Locked FY (`FinancialYear.isLocked`) rejects any write dated inside it (middleware check).

## Amount storage
- `Decimal(14,2)` for money, `Decimal(12,3)` for quantities, `Decimal(5,2)` for rates. Round half-up at line level, then sum; `roundOff` field absorbs paise rounding to nearest rupee on grand total.

## Stock
- `Product.stockQty` is a denormalized balance updated atomically (`UPDATE ... SET stock_qty = stock_qty + x`) in the same transaction as the StockMovement insert; StockMovement is the audit trail with `balanceAfter`.
