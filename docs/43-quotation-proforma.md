# Quotations and proforma invoices

Sales & Billing now includes **Quotations** and **Proforma invoices**. Both support create, full edit while open, PDF preview/print/download, explicit email, cancellation with a reason, and conversion. Customers and products use the existing searchable controls; product creation remains subject to its existing permission. Documents support GST/without GST, discounts, PO reference, subject, notes and terms.

Quotation → proforma and quotation → invoice are supported. A proforma can subsequently become an invoice. The conversion dialog selects the target, GST treatment, document date and validity/due date. An invoice uses the existing GST or without-GST invoice number series, stock policy, active/unlocked financial-year checks and invoice-created outbox/ledger flow. Conversion opens the resulting document and retains the source/result links. One source can be converted once; converted and cancelled records cannot be edited or converted again. Rejected conversions leave the source open, with no partial invoice or stock movement.

Quotations and proformas are **non-accounting documents** in their own table. They never enter invoice registers, customer outstanding, sales revenue, collections or GST reports until converted into an invoice. Their totals are estimates, not tax invoices. Their numbers use independent financial-year series: QUOTATION and PROFORMA_INVOICE. Configure existing series in Settings → Number series after the first document allocates it. Default proforma numbers are `PI/FY/00001`. Terms use the existing Settings → Terms entries for Quotation and Proforma Invoice. Resulting invoices use invoice terms.

Quotation/proforma email uses the tenant's SMTP settings and the customer's primary/additional invoice email addresses. Sending is explicit, attaches the PDF and records SENT/FAILED in notification logs. Creating a proforma does not automatically email it. A resulting invoice follows the tenant's existing invoice-notification configuration. Without-GST documents use the existing separate company profile when enabled. Existing PWA downloads remain online only.

API base: `/api/v1/sales-documents`. All routes authenticate and scope to the session tenant. `GET /` supports kind, status, search, FY, from/to, page and limit. `GET /:id` returns details; `GET /:id/pdf` returns a PDF with no-store headers. `POST /` creates; `PUT /:id` updates an open record using its version. `POST /:id/cancel` takes `{version, reason}`. `POST /:id/convert` takes `{version, target: "PROFORMA" | "INVOICE", chargeGst, documentDate, dueDate}`. `POST /:id/email` sends explicitly. Read/print/email use invoice:read; create uses invoice:create; edit/cancel use invoice:update; conversion requires both invoice:create and invoice:update. These reuse existing staff permissions without broadening access.

Conversion locks the source row and posts its target and reference in one transaction. Stale versions are rejected. Stored original line GST rates allow selecting GST at conversion even if the source was without GST; rates can be reviewed in the source editor. Subsequent invoice cancellations use the existing invoice workflow and do not reopen the original quotation automatically. Sales documents cannot be deleted; source references remain stable.

Migration `20261030180000_sales_documents` adds the separate table and proforma numbering type. Tenant-scoped backups automatically include documents and conversion links. Existing backups remain tied to their original schema/software version. Back up the database before applying migrations; never replace production with a local development database.

Appearance now defaults to Arial and light navigation in all five themes. Aptos and Calibri are additional professional font options under Appearance, with system fallbacks. Browser font choices affect application screens; printable documents use their own PDF typography.

Validation: unit route permission tests; isolated database workflow tests cover edit/version conflicts, cancellation, tenant isolation, quotation → proforma → invoice, GST/no-GST conversion, simultaneous requests, stock/FY rollback, backup contents, real PDF rendering and a local SMTP stand-in (no external email). Review the rendered sample PDFs and test mobile lists/forms/conversion dialogs before release.
